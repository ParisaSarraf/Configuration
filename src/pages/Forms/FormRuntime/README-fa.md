# لایهٔ نمایش و طراحی فرم (FormRuntime)

این پوشه دو کار را انجام می‌دهد:

1. **نمایش واقعی فرم** روی کاغذ A4 با زبان بصری فرم‌های اداری
   (خطوط نازک، نوار عنوان بخش، سربرگ سند، جدول مدرج‌دار، جای امضا).
2. **طراحی مستقیم روی همان خروجی** (WYSIWYG) در فرم‌ساز.

## فایل‌ها

| فایل | کاربرد |
| --- | --- |
| `form-runtime.css` | ظاهر فرم (کلاس‌های `fr-`) و قواعد چاپ A4 |
| `form-editor.css` | فقط ابزارهای طراحی (کلاس‌های `fw-`)؛ در چاپ حذف می‌شوند |
| `formElements.js` | انواع فیلد، خواندن ساختار جدول، اعتبارسنجی |
| `flowLayout.js` | موتور چیدمان ردیفی: از ترتیب + عرض به x/y/w/h |
| `FieldControl.jsx` | کنترل خام هر فیلد (قابل تایپ) |
| `SheetTable.jsx` | جدول با سلول‌های ادغام‌شده (rowspan/colspan) |
| `FormRenderer.jsx` | نمایش کامل فرم + `export function Element` |
| `FormLiveEditor.jsx` | حالت «طراحی روی فرم» |
| `sampleChangeRequestForm.js` | قالب آمادهٔ «درخواست تغییرات» |

## طراحی روی فرم (حالت پیش‌فرض)

در این حالت بوم طراحی دقیقاً همان کاغذی است که کاربر می‌بیند و چاپ می‌شود.

- مختصات x/y دستی تعیین نمی‌شود؛ فقط **ترتیب** و **عرض** مهم است.
- عرض: چیپ‌های ۱/۱ ، ۲/۳ ، ۱/۲ ، ۱/۳ ، ۱/۴ در نوار ابزار هر فیلد.
- ترتیب: کشیدن دستگیرهٔ `✣` یا دکمه‌های `↑ ↓`.
- افزودن: دکمهٔ `+` بین ردیف‌ها ← پالت انواع فیلد.
- تغییر عنوان: تایپ مستقیم روی نام فیلد در نوار ابزار.
- ارتفاع: کشیدن دستگیرهٔ لبهٔ پایین فیلد.
- `⧉` تکثیر · `⚙` تنظیمات کامل (کشوی کناری) · `✕` حذف.
- در همین حالت می‌توان داخل فیلدها تایپ کرد (آزمون واقعی فرم)؛
  این مقادیر جایی ذخیره نمی‌شوند و با دکمهٔ «پاک‌کردن نوشته‌های آزمایشی» پاک می‌شوند.

حالت قبلی («چیدمان آزاد» با درگwith‌‌و‌دراپ روی شبکه) با کلید بالای صفحه در دسترس است.

## ذخیره‌سازی

هیچ تغییری در API لازم نیست. مختصات مانند قبل در `css_class`
(`form-studio-x/y/w/h`) و ساختار جدول/سربرگ در `choices` ذخیره می‌شود.
