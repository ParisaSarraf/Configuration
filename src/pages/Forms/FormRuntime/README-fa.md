# راهنمای ساخت فرم‌های رسمی (مانند «درخواست تغییرات»)

## چه چیزی درست شد

1. **قفل بودن پیش‌نمایش**: قبلاً در `CategoryRightSidebar.jsx` و `FormBuilderStudio.jsx` همهٔ
   ورودی‌ها پراپ `disabled` داشتند؛ پس هیچ کس نمی‌توانست تایپ کند. حالا همهٔ
   کنترل‌ها از `FieldControl` می‌آیند که پراپ `readOnly` دارد:
   - بوم طراحی → `readOnly = true`
   - پیش‌نمایش و تکمیل فرم → `readOnly = false` (کاربر واقعاً تایپ می‌کند)
2. **ظاهر مینیمال**: رنگ‌های متعدد حذف شدند. پالت خروجی فقط: مشکی متن،
   خطوط طوسی، نوار عنوان آبی کم‌رنگ — در `form-runtime.css`.
3. **خروجی واقعی A4**: کاغذ 210×297میلی‌متر، قاب دور سند، `@media print` و
   `@page { size: A4 }`. دکمهٔ «چاپ / PDF» در نوار ابزار همان چیزی را چاپ می‌کند که دیده
   می‌شود.

## عناصر جدید پالت

| عنصر | کاربرد در نمونهٔ فرم |
| --- | --- |
| `doc_header` | سربرگ: لوگو + عنوان + شناسه سند / تاریخ بازنگری |
| `section_band` | نوارهای آبی: اطلاعات کلی، اثرات تغییر، بررسی و تاییدات، نتیجهٔ نهایی |
| `option_row` | ردیف‌های تک‌انتخابی افقی: هویت قطعه، دلیل تغییرات، محدودهٔ تأثیر |
| `sheet_table` | جدول با سلول ادغامی و ورودی درون سلول: جدول اثرات و جدول تاییدات |
| `signature` | خانه‌های امضا |
| `static_text` | متن ثابت؛ مانند «توزیع نسخ» |
| `divider` / `page_break` | خط جداکننده و شکست صفحه در چاپ |

## روش سریع: درج قالب آماده

در فرم‌ساز دکمهٔ **«درج قالب فرم رسمی»** را بزنید: ۲۱ عنصر درخواست تغییرات
(سربرگ، ۵ نوار بخش، فیلدهای اطلاعات کلی، جدول اثرات، جدول تاییدات، نتیجهٔ نهایی،
توزیع نسخ) یک‌جا ساخته می‌شوند و بعد می‌توانید هر کدام را جابجا یا ویرایش کنید.
منبع قالب: `sampleChangeRequestForm.js`.

نمونهٔ خروجی نهایی برای مقایسهٔ چشمی: `preview/change-request-demo.html`
(در مرورگر باز کنید — کاملاً تعاملی و قابل چاپ است).

## روش دستی: ساخت جدول با سلول ادغامی

عنصر «جدول پیشرفته» را اضافه کنید، رویش دوبار کلیک کنید و در کادر
«سلول‌های جدول (JSON)» بنویسید:

```json
[
  { "r": 0, "c": 0, "text": "بررسی کننده", "variant": "head", "align": "center" },
  { "r": 0, "c": 1, "text": "نظر", "variant": "head", "align": "center" },
  { "r": 0, "c": 2, "text": "امضا", "variant": "head", "align": "center" },
  { "r": 1, "c": 0, "text": "واحد طراحی", "variant": "sub" },
  { "r": 1, "c": 1, "type": "radio_row", "name": "design_opinion", "options": ["تایید", "رد"] },
  { "r": 1, "c": 2, "type": "signature", "name": "design_sign" }
]
```

کلیدهای هر سلول:

- `r` / `c`: شمارهٔ ردیف و ستون (از صفر)
- `rs` / `cs`: ادغام عمودی / افقی
- `variant`: `head` (سرستون آبی) ، `sub` (عنوان ردیف طوسی) ، `plain`
- `type`: اگر خالی باشد سلول فقط متن است؛ وگرنه یکی از:
  `text | textarea | number | date | checkbox | radio_row | select | signature`
- `name`: کلید ذخیرهٔ مقدار سلول (برای سلول‌های ورودی الزامی)
- `options`: گزینه‌های `radio_row` یا `select`
- `tall`: ردیف بلند (برای توضیحات و امضا)

تعداد ردیف در فیلد «حداقل مقدار» و تعداد ستون در «حداکثر مقدار» ذخیره می‌شود.

## نکتهٔ بک‌اند (مهم)

هیچ ستون جدیدی لازم نیست؛ عناصر جدید روی همین فیلدهای موجود سوار می‌شوند:
`field_type`، `choices`، `default_value`، `css_class`، `min_value`، `max_value`.
فقط دو شرط:

1. `field_type` مقادیر جدید را بپذیرد (یا محدودیت choice نداشته باشد):
   `option_row, signature, doc_header, section_band, static_text, divider, sheet_table, page_break`
2. `choices` علاوه بر رشته، آرایهٔ شیء (object) را هم در JSON ذخیره کند.
